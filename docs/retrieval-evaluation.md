# 检索质量验证记录

这里记录冻结 GIS 夹具的实际测量和保留的失败样本。它不替代最终提交对应的 GitHub CI，也不代表所有 QGIS provider 的完整目录已经达到相同分数。

## 固定输入与环境

夹具包含 58 项能力、一个关联调用示例以及 74 条中文、英文和混合语言需求。算法和工具 ID 已依据 QGIS 提交 `8f513743d20f78e88688e2174c59f6dc6a922b2c` 核对，并经过一次独立只读标签审查。完整 schema 不在这套小型回归夹具的覆盖范围内。

规范化为 UTF-8/LF 后的输入哈希：

| 文件 | SHA-256 |
| --- | --- |
| `catalog.json` | `50e992e4ed7fad885b2a589eae029717c20b367fd4f8d69f052fe353e0a7e40f` |
| `queries.json` | `803abd6530ab5aabd252eaa82cfe6d89bf9652d5c4cc697191cb86a47df8d9b0` |

初次本机报告的原始 CRLF 哈希分别为 `4985bceb67205e82ef199e0f611358ba8243101a47aafebd9d06984aa10e7b7d` 和 `2160c3a9728ce845cebe2696ff0e6aabdd1a1202430a7cf27f3bcfaaa4fd397a`。把规范 LF 文本还原成 CRLF 可精确重现这两个哈希，查询、标签、目录内容和 dataset revision 都没有改变。

模型为 `embeddinggemma-2-Q8_0`，revision `bfcd298762cc34d0357ece5ebdd31791a3a374d8`，使用 768 维、mean pooling 和 L2 归一化。下列基线使用 `capability-json-v1` 文档版本和 `embeddinggemma-search-v1` 提示版本。

## 2026-10-29 基线实测

所有标注查询通过实际编译出的 `qctsm-cli` 调用服务。首条查询同时通过 HTTP 检查候选顺序与原始 JSON，两个环境均一致。每个环境使用独立空 SQLite，退出前清理测试来源并正常关闭自建服务。

全目录 payload 为 12,378 个紧凑 JSON UTF-8 字节。这里比较的是 JSON 体积，不能当作模型 tokenizer 的 token 数。CLI 时延包含进程启动与状态轮询，模型可能已在索引期间加载，首个查询不等于模型冷启动。远端硬件未在本次评测中核实。

上述两次本机工程验证使用相同服务可执行文件 SHA-256 `997d75c3a6c8335bb5fa29cb8c38e2d5b58d83e0378921cd7e940ca7c73f7044`，CLI SHA-256 为 `69d04d56dedb2883253118760ae5060f49d4f41b042dec78dcf4e8e2eaf40777`。运行时尚未绑定最终 GitHub 提交。CI 报告另外记录提交、run 和 attempt，不能用这组本地哈希替代 CI 证据。

## 保留的失败与修复依据

最初远端索引在 47 / 59 条记录后出现 `network_error: Connection closed`，该次运行没有进入标注查询，验收失败。后续将索引改成每批最多八个文档片段，并对明确的暂时网络错误执行最多两次额外重试。重试共用原超时预算，协议、认证和向量校验错误不重试。更新后的远端测试完成了全部索引与查询。

基线唯一未进入前八名的样本为 `gis-033`：

> 提取人口字段超过十万的行政区形成新图层

标注能力 `native:extractbyattribute` 正确。英文同意图 `gis-034` 通过。额外的 Top 58 诊断显示，正确算法在中文请求中排第 10 位，所有候选的词法得分都是零，失败发生在中文到英文文档的语义排序阶段。诊断查询不计入 74 条验收分数，也没有放宽正式 Top N。

该样本与首轮网络失败都保留在验证报告中。后续通用文档表示或检索算法修复必须继续运行原来的 74 条查询，记录旧版本与新版本的完整差异，不能删除样本或改标签以隐藏失败。

运行命令、评分定义和报告字段见 [测试与检索质量](testing.md)。
